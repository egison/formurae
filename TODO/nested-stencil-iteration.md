# 入れ子のステンシル反復と全領域集計

2026-09-12 のテイラー・クエット流れの設計相談で合意した方針を記録する．
ユーザーはこの用途について Formura 本体の拡張も含めた設計を希望している．
以下の構文と実行規則は設計段階であり，まだ実装されていない．

## 現状

Formurae は `.fme -> Egison -> FEIR -> .fmr -> Formura -> C` の順で計算を生成する．
FEIR は数式と実行する処理を受け渡す中間表現である．
外側の `init` は初期状態を作り，`step` は状態を更新する．実行用 C の `main` は
例題ごとに用意しており，生成された `Formura_Forward` を繰り返し呼び出す．

Formura は通常の関数定義のうち `init`・`step` を必須，`first_step`・`filter` を
任意の処理として認識する．終了判定を行う `check` や，実行時の内側の反復はない．
YAML の `reduces` は，初期化と `Formura_Forward` の完了時点の状態を全領域で
集計して C 側へ渡す．ステップ途中の式や終了判定へ渡す言語機能にはなっていない．

[既存のポアソン例](../upstream/reduce-test/poisson1d.fmr)では，近傍の値から解を
繰り返し更新するヤコビ反復を記述しているが，反復の制御は
[実行用 C](../upstream/reduce-test/poisson_check.c)にある．

## 欠けているもの

- `step` の途中に，独立した状態を持つ反復計算を記述する仕組み．
- 全領域の最大値・和などを実行時の値として後続の式と終了判定に使う仕組み．
- 反復状態，外側の固定入力，反復ごとの一時値を区別する規則．
- 収束するまで後続へ進まず，未収束や数値異常で実行を停止する仕組み．
- 内側の反復と外側の物理時間を分けて，通信とブロッキングを生成する仕組み．

## 設計判断

### 名前付きの反復ブロック

内側の計算は関数化せず，外側の処理の中に `iterate NAME:` として書く．
ブロックは `field` と `init`・`step`・`check` を持つ．
`return`・`returns`・`result:` は設けない．

次は軸対称なテイラー・クエット流れの圧力補正を示す擬似コードである．
速度 `u` は半径方向・周方向・軸方向の三成分を持ち，`p` は密度で割った圧力を表す．
数値解法の全体ではなく反復構文の例であり，初期条件と境界宣言の詳細は省略する．

```text
step:
  local u_star = predict_velocity(u, p, nu, dt)
  local rhs = div_h(u_star) / dt

  iterate pressure:
    field phi : scalar @ collocated

    max_steps = max_iters
    check_every = check_interval

    init:
      phi = 0

    step:
      local residual = rhs - L(phi)
      phi' = phi + omega * residual / poisson_diagonal

    check:
      let residual_norm = global_max(abs(rhs - L(phi)))
      residual_norm <= divergence_tolerance / dt

  u' = u_star - dt * grad_h(pressure.phi)

  local p_next = p + pressure.phi
  let p_mean =
    global_sum(cell_volume * p_next) / global_sum(cell_volume)

  p' = p_next - p_mean
```

`predict_velocity` は移流・粘性・遠心力・現在の圧力による予測と回転壁の速度条件の
適用を表す．`div_h` と `grad_h` は格子上の発散と勾配であり，境界も含めて
`L(phi) = div_h(grad_h(phi))` と整合させる．`poisson_diagonal` はこの演算子の
中心点の係数で，この符号では負になる．`omega` は反復の更新量を調整する重みである．
これらの補助計算も Formurae に記述する．

上の射影では，残差 `rhs - L(phi)` と補正後の速度の発散との関係が
`div_h(u_next) = dt * (rhs - L(phi))` になるため，発散の許容値から終了条件を決める．
円筒座標の `cell_volume` は半径による体積の違いを含む．実際の例題では右辺と壁からの
流出入の整合も検査する．壁での圧力補正の条件は予測速度と整合させ，物理的な圧力の
境界条件と区別する．これらの境界宣言の詳細は，反復構文とは別に詰める．

### 状態と変数の参照範囲

- ブロックに入るたびに `init` を一度実行し，内側の状態を初期化する．
- 外側の場・スカラー値は読み取り専用で参照し，内側の反復中には変化しない．
  外側の値を内側の `step` から更新することはできない．
- 無印の `phi` はその回の開始時の状態，`phi'` は次の反復の状態である．
  定義済みの `a'` を後続の式が明示的に読む規則も既存の `step` にそろえる．
  `step` 全体が完了した時点で次の状態が確定する．
- `check` は確定した現在の状態を読み，状態を更新しない．最後の式は全領域で共通の
  真偽値とする．`check` 内の `return` や戻り値のレコードは使わない．
- `init`・`step`・`check` の中の `local`・`let` は，それぞれの区分内でのみ参照できる．
- 正常終了後は，外側から `pressure.phi` のように内側の宣言済み状態を読み取れる．
  書き換えることはできない．`pressure.iterations` は実行した内側の `step` の回数である．
  これらの参照はブロックより後の，同じ外側の処理の中で有効である．
- 外側の次の物理時間ステップで同じブロックに入ると再び初期化する．前回の解を
  初期値に使う場合は，外側で保持した値を `init` が明示的に参照する．

### 判定の順序と失敗時の動作

1. ブロックの固定入力と実行設定を確定し，`init` を実行する．
2. 更新回数ゼロで `check` を実行する．真なら，更新せずに正常終了する．
3. 未収束なら `step` を指定回数実行してから再び `check` を実行する．
4. 真になった場合だけブロックより後の計算へ進む．

`max_steps` はこのブロック内の更新回数の上限で，非負の整数とする．
`check_every` は正の整数で，既定値は 1 とする．上限まで残った回数が
`check_every` より少なければ，その残りだけ更新して検査する．上限を超えて実行しない．
上限ちょうどで `check` が真になった場合も正常終了とする．

上限に達しても偽の場合，または判定時の状態や計算値に NaN・無限大などの数値異常が
ある場合は，診断を出して実行を停止する．最大値などの集計で数値異常を隠さない．
外側の時間ステップは完了させず，物理時刻も進めない．

これは反復の標準動作である．呼び出し側に収束確認の `require` を書かせず，
`pressure.status` も通常の参照項目に設けない．診断には少なくともブロックの名前と
ソース位置，更新回数，停止理由を含める．判定に使った数値の表示方法は実装時に詰める．

### 全領域集計と実行順序

`global_sum`・`global_max` などは，領域分割された格子全体を集計し，全プロセスで
共通の実行時の値を返す．境界計算のために複製した格子点は重複して数えない．
集計は `check` に限定せず，`init`・`step` と外側の計算でも使用できる．
その値を使う後続の計算は，集計が完了してから実行する．

反復への進入と終了，集計の実行順序は全プロセスでそろえる．格子点ごとに異なる条件の
下で反復や全領域集計を実行する記述は認めない．数値異常や上限到達時も全体で停止し，
一部のプロセスだけが後続へ進んだり通信を待ち続けたりしないようにする．

### Formura への変換

反復ブロックを中間表現と `.fmr` まで保持し，内側の `init`・`step`・`check` と，
それらを繰り返す制御部分を Formura が C に生成する．数式の記号処理中に反復を
実行したり，Formurae が Formura を迂回して反復用 C を生成したりしない．

内側の `init` は反復状態だけを初期化する．外側と格子・並列通信の環境を共有し，
MPI の初期化や外側のモデルの初期化を繰り返さない．反復ごとの境界処理を適用し，
内側の更新回数を外側の物理時間から分離する．

時間方向のブロッキング，すなわち複数回の更新をまとめる最適化は，全領域集計や
判定を挟まない連続した更新を対象にする．`check_every` を最適化によって変更しない．
最後の更新回数がブロック幅に満たない場合も，指定された回数だけ実行する．
固定入力も含めた参照範囲を調べ，必要な近傍領域の通信と境界処理を生成する．

外側の実行用 C は従来どおり `Formura_Forward` を呼び出せる構成とする．
内側の圧力求解を実行用 C に手書きしない．停止時の C 側への通知と MPI 全体の
終了方法，反復用配列の確保と再利用の詳細は，コード生成の設計で決める．

## 差し込み口

- Formurae の `src/Formurae/Syntax.hs` と `src/Formurae/Pre/Parse.hs`：
  入れ子の処理と区分，名前の参照範囲，実行設定を表す構文を追加する．
- `src/Formurae/Pre/TypeCheck.hs` と `src/Formurae/Pre/Effect.hs`：
  場と全領域で共通の値，外側の固定入力と内側の更新対象を区別して検査する．
- `src/Formurae/Pre/EmitEgison.hs`，`src/Formurae/FEIR/`，`lib/` の FEIR 出力：
  反復・集計・処理順序・ソース位置を保って受け渡す．
- `src/Formurae/Post/Compile.hs` と `src/Formurae/Post/FMR.hs`：
  反復単位の格子配置と一時的な場を決め，拡張後の Formura 構文へ変換する．
- Formura の `Parser.hs`・`Syntax.hs` と `OrthotopeMachine/`：
  現在の単一の `init`・`step` に加え，内側の反復と実行時スカラーを表現する．
- Formura の `Generator/Templates.hs` など：
  反復制御，ステップ途中の全領域集計，失敗時の停止，通信と境界処理を生成する．
  現在の `genReduces` は呼び出し完了後の状態の集計なので，その配置のままでは不足する．

## 完了条件

- 入れ子の `init`・`step`・`check` と終了後の状態参照が通常の生成経路で動作する．
  外側の値への書き込みや，区分外の一時値の参照をソース位置付きで検出する．
- 初期状態での収束，通常の収束，上限ちょうどでの収束，未収束での上限到達，
  判定間隔で割り切れない上限，数値異常を検証する．失敗時に後続処理や外側の時刻更新が
  実行されないことを確認する．
- 固定入力の保持，複数の反復状態の更新前後の参照，ブロックへの再進入時の初期化を
  検証する．内側の反復回数で外側の物理時刻が変わらないことを確認する．
- 格子全体の集計が一時的な場にも使え，その値を後続の式に渡せる．単一プロセスと
  分割実行で，適切な浮動小数点の許容誤差の下で同じ計算を行うことを確認する．
- 同じ判定間隔の下で，ブロッキングの有無と領域分割の違いによる解・判定の整合を
  検証する．境界と固定入力を含む例を用い，未収束・数値異常でも通信待ちが残らない．
- 単独のポアソン問題と速度補正の例で，解の誤差と方程式の残差，補正後の発散を
  検証する．これらの数値計算を Formurae に記述する．
