# 入れ子のステンシル反復，最外側の終了判定，全領域集計

2026-09-12 のテイラー・クエット流れの設計相談で合意した方針を記録する．
ユーザーはこの用途について Formura 本体の拡張も含めた設計を希望している．
以下の構文と実行規則は設計段階であり，まだ実装されていない．
同日の追加要件として，外側の物理時間と内側の求解反復の両方で，時間方向の
ブロッキングによる効率化を目指す．この二重の最適化の具体的な実行順序と性能は未検証である．

## 現状

Formurae は `.fme -> Egison -> FEIR -> .fmr -> Formura -> C` の順で計算を生成する．
FEIR は数式と実行する処理を受け渡す中間表現である．
外側の `init` は初期状態を作り，`step` は状態を更新する．実行用 C の `main` は
例題ごとに用意しており，生成された `Formura_Forward` を繰り返し呼び出す．

Formura は通常の関数定義のうち `init`・`step` を必須，`first_step`・`filter` を
任意の処理として認識する．終了判定を行う `check` や，実行時の内側の反復はない．
YAML の `reduces` は，初期化と `Formura_Forward` の完了時点の状態を全領域で
集計して C 側へ渡す．ステップ途中の式や終了判定へ渡す言語機能にはなっていない．

[既存のポアソン例](../upstream/reduce-test/poisson1d.fmr)では，近傍の値から解を
繰り返し更新するヤコビ反復を記述しているが，反復の制御は
[実行用 C](../upstream/reduce-test/poisson_check.c)にある．

## 欠けているもの

- `step` の途中に，独立した状態を持つ反復計算を記述する仕組み．
- 最外側にも任意の `check` を置き，モデル側で終了条件を指定する仕組み．
- 全領域の最大値・和などを実行時の値として後続の式と終了判定に使う仕組み．
- 反復状態，外側の固定入力，反復ごとの一時値を区別する規則．
- 収束するまで後続へ進まず，未収束や数値異常で実行を停止する仕組み．
- 内側の反復と外側の物理時間を分けて，通信とブロッキングを生成する仕組み．
- 内側だけでなく，内側の求解を含む外側の複数ステップにも時間方向のブロッキングを
  適用し，外側を最適化したことによる効果を別に評価する仕組み．

## 設計判断

### 名前付きの反復ブロック

内側の計算は関数化せず，外側の処理の中に `iterate NAME:` として書く．
ブロックは `field` と `init`・`step`・`check` を持つ．
`return`・`returns`・`result:` は設けない．

最外側のモデルにも，`init`・`step` と同列に任意の `check` を置ける．
内側の `iterate` は `check` を必須とし，最外側では省略できる．

次は軸対称なテイラー・クエット流れの圧力補正を示す擬似コードである．
速度 `u` は半径方向・周方向・軸方向の三成分を持ち，`p` は密度で割った圧力を表す．
数値解法の全体ではなく反復構文の例であり，初期条件と境界宣言の詳細は省略する．

```text
step:
  local u_star = predict_velocity(u, p, nu, dt)
  local rhs = div_h(u_star) / dt

  iterate pressure:
    field phi : scalar @ collocated

    max_steps = max_iters
    check_every = check_interval

    init:
      phi = 0

    step:
      local residual = rhs - L(phi)
      phi' = phi + omega * residual / poisson_diagonal

    check:
      let residual_norm = global_max(abs(rhs - L(phi)))
      residual_norm <= divergence_tolerance / dt

  u' = u_star - dt * grad_h(pressure.phi)

  local p_next = p + pressure.phi
  let p_mean =
    global_sum(cell_volume * p_next) / global_sum(cell_volume)

  p' = p_next - p_mean
```

`predict_velocity` は移流・粘性・遠心力・現在の圧力による予測と回転壁の速度条件の
適用を表す．`div_h` と `grad_h` は格子上の発散と勾配であり，境界も含めて
`L(phi) = div_h(grad_h(phi))` と整合させる．`poisson_diagonal` はこの演算子の
中心点の係数で，この符号では負になる．`omega` は反復の更新量を調整する重みである．
これらの補助計算も Formurae に記述する．

上の射影では，残差 `rhs - L(phi)` と補正後の速度の発散との関係が
`div_h(u_next) = dt * (rhs - L(phi))` になるため，発散の許容値から終了条件を決める．
円筒座標の `cell_volume` は半径による体積の違いを含む．実際の例題では右辺と壁からの
流出入の整合も検査する．壁での圧力補正の条件は予測速度と整合させ，物理的な圧力の
境界条件と区別する．これらの境界宣言の詳細は，反復構文とは別に詰める．

### 状態と変数の参照範囲

- ブロックに入るたびに `init` を一度実行し，内側の状態を初期化する．
- 外側の場・スカラー値は読み取り専用で参照し，内側の反復中には変化しない．
  外側の値を内側の `step` から更新することはできない．
- 無印の `phi` はその回の開始時の状態，`phi'` は次の反復の状態である．
  定義済みの `a'` を後続の式が明示的に読む規則も既存の `step` にそろえる．
  `step` 全体が完了した時点で次の状態が確定する．
- `check` は確定した現在の状態を読み，状態を更新しない．最後の式は全領域で共通の
  真偽値とする．`check` 内の `return` や戻り値のレコードは使わない．
- `init`・`step`・`check` の中の `local`・`let` は，それぞれの区分内でのみ参照できる．
- 正常終了後は，外側から `pressure.phi` のように内側の宣言済み状態を読み取れる．
  書き換えることはできない．`pressure.iterations` は実行した内側の `step` の回数である．
  これらの参照はブロックより後の，同じ外側の処理の中で有効である．
- 外側の次の物理時間ステップで同じブロックに入ると再び初期化する．前回の解を
  初期値に使う場合は，外側で保持した値を `init` が明示的に参照する．

### 内側の判定の順序と失敗時の動作

1. ブロックの固定入力と実行設定を確定し，`init` を実行する．
2. 更新回数ゼロで `check` を実行する．真なら，更新せずに正常終了する．
3. 未収束なら `step` を指定回数実行してから再び `check` を実行する．
4. 真になった場合だけブロックより後の計算へ進む．

`max_steps` はこのブロック内の更新回数の上限で，非負の整数とする．
`check_every` は正の整数で，既定値は 1 とする．上限まで残った回数が
`check_every` より少なければ，その残りだけ更新して検査する．上限を超えて実行しない．
上限ちょうどで `check` が真になった場合も正常終了とする．

上限に達しても偽の場合，または判定時の状態や計算値に NaN・無限大などの数値異常が
ある場合は，診断を出して実行を停止する．最大値などの集計で数値異常を隠さない．
外側の時間ステップは完了させず，物理時刻も進めない．

これは反復の標準動作である．呼び出し側に収束確認の `require` を書かせず，
`pressure.status` も通常の参照項目に設けない．診断には少なくともブロックの名前と
ソース位置，更新回数，停止理由を含める．判定に使った数値の表示方法は実装時に詰める．

### 任意の最外側の check

最外側の `check` も，状態を更新せず，最後の式として全領域で共通の真偽値を返す．
例えば，流れが時間によって変化しない定常状態に近づいたことを終了条件にできる．

```text
init:
  ...

step:
  ...
  iterate pressure:
    ...
    init:
      ...
    step:
      ...
    check:
      global_max(abs(rhs - L(phi))) <= pressure_tolerance
  ...

check:
  global_max(steady_residual(u, p)) <= steady_tolerance
```

`steady_residual` は，現在の状態が定常状態の方程式をどれだけ満たしているかを表す
非負の指標を，Formurae のステンシル演算で計算する補助関数の略記である．
外側の `step` 内の一時値を最外側の `check` から直接参照することはできない．
現在のモデルの状態から計算するか，必要な量を外側の状態として保持する．

- `check` がある場合は，モデルの初期化完了時と，最外側の `check_every` で指定した
  更新回数ごとに判定する．既定の間隔は 1 で，内側の判定間隔とは独立である．
  `first_step` を使うモデルでは初期化のためのその処理も終えてから最初の判定を行う．
- 更新後の判定は，内側の反復と外側の更新，その時点で適用する `filter`，現在の
  ステップ数の更新が完了した状態を読む．内側の一回の更新では外側の判定を行わない．
- 真になったらモデルの時間発展を正常終了する．初期状態で真なら物理時間を進めない．
  最終状態と実行したステップ数を保存し，呼び出し側で出力や終了処理を行えるようにする．
- 終了が確定した後は，追加の更新を行わない．最外側の正常終了に `require` は不要で，
  プロセスをエラー終了させる処理でもない．数値異常や内側の反復の失敗は，従来の設計
  どおり全体の異常終了として扱う．
- `check` を省略した場合，モデル側の終了条件は設けず，実行用 C が総ステップ数などを
  決める．内側の `iterate` に `check` があるかどうかとは独立である．

終了条件の評価は生成された計算本体が担当する．実行用 C はその完了通知を読んで
ループを終了するため，残差などの数値計算や判定式を書き直す必要はない．
C 側の関数名と具体的な受け渡し方法は未決定だが，例えば次のような形を取れる．

```c
/* 新しい C 接続方法の案．現在の生成 API にはない． */
Formura_Init(&argc, &argv, &n);
while (!Formura_Finished(&n)) {
    Formura_Forward(&n);
    /* 必要な時点の出力 */
}
/* 初期状態で終了した場合も含め，最終状態の出力と終了処理を行う． */
Formura_Finalize();
```

この例では完了通知を生成側が保持し，完了後の `Formura_Forward` は更新せずに戻る．
`check` 付きモデルの実行用 C も，完了通知を読んで終了するように更新する．
`main` の自動生成はこの追加の前提としない．

### 全領域集計と実行順序

`global_sum`・`global_max` などは，領域分割された格子全体を集計し，全プロセスで
共通の実行時の値を返す．境界計算のために複製した格子点は重複して数えない．
集計は `check` に限定せず，`init`・`step` と外側の計算でも使用できる．
その値を使う後続の計算は，集計が完了してから実行する．

反復への進入と終了，集計の実行順序は全プロセスでそろえる．格子点ごとに異なる条件の
下で反復や全領域集計を実行する記述は認めない．数値異常や上限到達時も全体で停止し，
一部のプロセスだけが後続へ進んだり通信を待ち続けたりしないようにする．

### Formura への変換

反復ブロックを中間表現と `.fmr` まで保持し，内側の `init`・`step`・`check` と，
それらを繰り返す制御部分を Formura が C に生成する．数式の記号処理中に反復を
実行したり，Formurae が Formura を迂回して反復用 C を生成したりしない．

内側の `init` は反復状態だけを初期化する．外側と格子・並列通信の環境を共有し，
MPI の初期化や外側のモデルの初期化を繰り返さない．反復ごとの境界処理を適用し，
内側の更新回数を外側の物理時間から分離する．

時間方向のブロッキング，すなわち複数回の更新の間でデータを再利用してメモリ転送や
通信を減らす最適化は，外側と内側の両方を対象にする．全領域集計と終了判定が課す
依存関係を保って実行順序を組み替える．具体的な検討課題は次節に記す．

外側の実行用 C は従来どおり `Formura_Forward` を呼び出せる構成とする．
内側の圧力求解や最外側の終了判定式を実行用 C に手書きしない．最外側の正常終了を
通知して最終状態を読めることと，失敗時に MPI 全体を停止することを区別する．
具体的な C 側との接続方法，反復用配列の確保と再利用の詳細は，コード生成の設計で決める．

### 外側と内側の両方の時間方向ブロッキング

**要件は両方の反復で効率化することである．** 内側だけにブロッキングを適用して
完了とはしない．外側のループを単に数回ずつ呼び出す形にまとめるだけでも，
データの再利用が増えなければ外側の時間方向ブロッキングを実現したことにはならない．
外側の複数の物理時間ステップと，内側の複数の求解反復にまたがる再利用を目指す．

外側のまとめる幅を `T_outer`，内側の幅を `T_inner` として独立に調整し，両方を
組み合わせて生成できる構成にする．これらは最適化の設定であり，`check_every` という
終了条件を検査する間隔とは別である．設定の具体的な記法は未決定である．

#### 依存関係として解決する必要があること

現行 Formura のブロッキングは，一つの格子領域について同じ `step` を複数回実行する．
これをそのまま二重に呼び出すだけでは，内側の全領域集計と整合しない．
例えば，ある領域だけが圧力求解を終えて次の物理時刻へ進むと，ほかの領域の結果を
含む収束判定をまだ確認できていない．

さらに，集計の結果は用途を分けて扱う必要がある．

- 終了判定は，どの反復状態を使って後続へ進むかを決める依存関係を作る．
- 圧力の体積平均などは，後続の数式が実際の集計値を読む依存関係を作る．
  終了する回数を仮定できても，必要な集計値を無視してよいことにはならない．
- 外側の `check`，右辺の整合検査，適用時点の `filter` なども実行順序に含める．
  例題からこれらを外すことで外側の最適化が成立したことにはしない．

そのため，現在の全領域判定付きの圧力求解について，外側の完全な複数ステップを
一つの小領域で効率よく進められる方式が確立したとは，まだ言えない．
この問題を未解決の実装・評価課題として残し，外側の効率化という要件を維持する．

#### 検討する方式

まず，外側の予測・内側の初期化と反復・残差・補正・次の外側の予測を一続きの
依存関係として表現する．場の近傍参照だけでなく，実行時スカラーの値，終了判定，
固定入力，境界，更新前後の状態も記録する．この情報から複数段階と反復境界をまたぐ
タイル化，すなわち小領域ごとに複数の計算をまとめる順序を検討する．
適用できる一部分を融合できても，外側全体の要件を満たしたかは別に評価する．

全領域の終了判定をまたぐ候補として，投機実行も調べる．これは，後続が実行されると
仮定して先に計算し，判定が確定した後に結果を採用するか取り消す方法である．
採用済みの方式ではなく，正しさと追加のメモリ・再計算・通信費用を調べる研究候補とする．
検討に際しては，少なくとも次を満たす必要がある．

- 元の実行で最初に `check` が真になる時点と状態を保つ．一般の `check` が，一度真に
  なった後ずっと真であるとは仮定しない．区間末尾だけの判定で途中の真を見落とさない．
- 内側の終了回数を誤って仮定した場合，その状態から計算した外側の候補も取り消す．
  確定済みの状態へ戻れるよう，保存する状態と必要な一時配列を定める．
- 出力，外側の時刻，公開する反復回数，正常終了やエラーは，元の実行順序に対応する
  確定済みの結果だけに基づく．不要になった候補内の数値異常で実行全体を停止しない．
  副作用を持つ外部呼び出しを先行させない．
- 集計値を数式が読む場合は，実際の値を得てから実行するか，同じ計算結果を保つ変換を
  別途示す．終了回数の仮定だけで，未知の集計値への依存を解消した扱いにしない．
- 全プロセスの検証・取り消し・通信の順序をそろえ，未確定の値で確定状態を上書きしない．

単純な先行実行を行わない方式では，集計結果を必要とする地点までの連続した計算を
まとめることが基本になる．その範囲と費用を測定し，外側にも十分な再利用を作れる
方式と比較する．いずれも，効率化のために許容誤差や `check_every` を変更したり，
圧力求解を少数の固定回数に置き換えたりしない．上限を超えた更新を確定させない．

#### 参考にする先行研究と適用上の区別

- Reguly ほかの [Loop Tiling in Large-Scale Stencil Codes at Run-time with OPS](https://arxiv.org/abs/1704.00693)
  は，複数のステンシル処理の依存関係を実行時に調べてまとめる．制御判断のために
  集計値が必要になる地点では，待機していた処理を実行する（§IV-A）．
- Li・Song の [Automatic Tiling of Iterative Stencil Loops](https://www.cs.purdue.edu/homes/ci/draft/toplas.pdf)
  は，途中終了を含む反復に投機実行と状態の復元を使う方式を扱う（§6.3）．
  同節の区間末尾だけを調べる方式には，終了条件が一度真になると真のままという前提がある．
  任意の `check` と，集計値を次の計算に使う二重反復への一般解とは扱わない．

#### 外側の効率化を確認する評価

同じ問題・初期状態・格子・時間刻み・許容誤差・判定間隔・並列構成で，次の四条件を
比較する．比較のための数値計算も Formurae に記述する．

1. 外側なし・内側なし．
2. 外側なし・内側あり．
3. 外側あり・内側なし．
4. 外側あり・内側あり．

外側の最適化については 1 と 3，2 と 4 の比較で効果を分離する．実行時間だけでなく，
メモリ転送量，近傍領域の通信量，全領域集計の回数と待ち時間，追加の計算量と配列量を
記録する．先行実行を使う場合は取り消しと再実行も費用に含める．
正しさの比較では最終値に加えて，所定の判定時点と終了時点，更新回数，失敗時の動作を
確認する．集計順序による浮動小数点誤差が終了判断へ与える影響も切り分ける．

## 差し込み口

- Formurae の `src/Formurae/Syntax.hs` と `src/Formurae/Pre/Parse.hs`：
  入れ子の処理と区分，最外側の任意の `check`，名前の参照範囲，実行設定を表す構文を追加する．
- `src/Formurae/Pre/TypeCheck.hs` と `src/Formurae/Pre/Effect.hs`：
  場と全領域で共通の値，外側の固定入力と内側の更新対象を区別して検査する．
- `src/Formurae/Pre/EmitEgison.hs`，`src/Formurae/FEIR/`，`lib/` の FEIR 出力：
  反復・集計・処理順序・ソース位置を保って受け渡す．
- `src/Formurae/Post/Compile.hs` と `src/Formurae/Post/FMR.hs`：
  反復単位の格子配置と一時的な場を決め，拡張後の Formura 構文へ変換する．
- Formura の `Parser.hs`・`Syntax.hs` と `OrthotopeMachine/`：
  現在の単一の `init`・`step` に加え，内側の反復と実行時スカラーを表現する．
- Formura の `Generator/Templates.hs` など：
  反復制御，ステップ途中の全領域集計，最外側の終了判定と完了通知，失敗時の停止，
  通信と境界処理を生成する．
  現在の `genReduces` は呼び出し完了後の状態の集計なので，その配置のままでは不足する．
- Formura の計算の依存関係を調べる処理とブロッキング生成：
  外側と内側をまたぐ参照範囲，集計への依存，状態の保存と再利用を表現し，
  両方の反復を最適化する実行順序を検討・生成する．

## 完了条件

- 入れ子の `init`・`step`・`check` と終了後の状態参照が通常の生成経路で動作する．
  外側の値への書き込みや，区分外の一時値の参照をソース位置付きで検出する．
- 最外側の `check` の有無，初期状態での正常終了，更新後の正常終了，内側と異なる
  判定間隔を検証する．終了後の追加更新を行わず，最終状態を C 側から出力できる．
  初期化用の `first_step` と更新後の `filter` がある場合の判定順序も確認する．
- 初期状態での収束，通常の収束，上限ちょうどでの収束，未収束での上限到達，
  判定間隔で割り切れない上限，数値異常を検証する．失敗時に後続処理や外側の時刻更新が
  実行されないことを確認する．
- 固定入力の保持，複数の反復状態の更新前後の参照，ブロックへの再進入時の初期化を
  検証する．内側の反復回数で外側の物理時刻が変わらないことを確認する．
- 格子全体の集計が一時的な場にも使え，その値を後続の式に渡せる．単一プロセスと
  分割実行で，適切な浮動小数点の許容誤差の下で同じ計算を行うことを確認する．
- 同じ判定間隔の下で，ブロッキングの有無と領域分割の違いによる解・判定の整合を
  検証する．境界と固定入力を含む例を用い，未収束・数値異常でも通信待ちが残らない．
- 外側と内側を独立に切り替える四条件で検証し，内側だけの場合と比較した外側の
  最適化の効果を示す．全領域の圧力求解を含む例で，意味を保つ実行順序と実際の
  データ再利用を示す．外側が単なる呼び出し回数のまとめになっている場合は未完了とする．
- 単独のポアソン問題と速度補正の例で，解の誤差と方程式の残差，補正後の発散を
  検証する．これらの数値計算を Formurae に記述する．
