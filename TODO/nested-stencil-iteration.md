# 入れ子のステンシル反復，最外側の終了判定，全領域集計

2026-09-12 のテイラー・クエット流れの設計相談で合意した方針を記録する．
ユーザーはこの用途について Formura 本体の拡張も含めた設計を希望している．
以下の構文と実行規則は設計段階であり，まだ実装されていない．
同日の相談では，いったん内外両方の時間方向ブロッキングを要件としたが，その後，
ユーザーは外側への適用が難しい場合は今回の対象から外す方針を示した．
これを受け，外側・内側の各更新の空間並列化と，内側の求解反復の時間方向ブロッキングを
実装対象とする．圧力求解を含む外側の複数ステップをまたぐブロッキングは完了条件に含めない．

## 現状

Formurae は `.fme -> Egison -> FEIR -> .fmr -> Formura -> C` の順で計算を生成する．
FEIR は数式と実行する処理を受け渡す中間表現である．
外側の `init` は初期状態を作り，`step` は状態を更新する．実行用 C の `main` は
例題ごとに用意しており，生成された `Formura_Forward` を繰り返し呼び出す．

Formura は通常の関数定義のうち `init`・`step` を必須，`first_step`・`filter` を
任意の処理として認識する．終了判定を行う `check` や，実行時の内側の反復はない．
YAML の `reduces` は，初期化と `Formura_Forward` の完了時点の状態を全領域で
集計して C 側へ渡す．ステップ途中の式や終了判定へ渡す言語機能にはなっていない．

[既存のポアソン例](../upstream/reduce-test/poisson1d.fmr)では，近傍の値から解を
繰り返し更新するヤコビ反復を記述しているが，反復の制御は
[実行用 C](../upstream/reduce-test/poisson_check.c)にある．

## 欠けているもの

- `step` の途中に，独立した状態を持つ反復計算を記述する仕組み．
- 最外側にも任意の `check` を置き，モデル側で終了条件を指定する仕組み．
- 全領域の最大値・和などを実行時の値として後続の式と終了判定に使う仕組み．
- 反復状態，外側の固定入力，反復ごとの一時値を区別する規則．
- 収束するまで後続へ進まず，未収束や数値異常で実行を停止する仕組み．
- 内側の反復と外側の物理時間を分け，各更新の空間並列化と通信を生成する仕組み．
- 内側の求解反復に時間方向のブロッキングを適用し，所定の終了判定を保つ仕組み．

## 設計判断

### 二つの反復軸と空間方向の並列化

物理時間，求解の反復回数，空間の格子点を区別する．表層構文に明示する反復は
前二者であり，場の式に含まれる格子点ごとの計算は Formura が生成する．

| 対象 | 一回の更新が表すもの | 今回の並列化・最適化 |
|---|---|---|
| 外側の `step`，回数 `n` | 圧力求解と速度補正を含む，物理時間の一ステップ | 予測・補正など，各段階の空間並列化 |
| 内側の `iterate pressure` の `step`，回数 `k` | 同じ物理時刻での圧力補正の近似解の更新 | 各更新の空間並列化と，複数反復間のブロッキング |
| 空間の格子点 | 各格子点とその近傍の値を使う計算 | プロセスへの領域の分担と，担当領域内の並列化 |

`k` は空間を走査する添字ではなく，近似解を更新した回数である．外側の速度予測・
補正も，内側の初期化・圧力更新・残差計算も，それぞれ格子全体に対する処理になる．
`iterate pressure` は全プロセスが協調する一つの求解を表す．ユーザーに空間の `for` や
並列化専用の `iterate` は書かせない．内側の一回の更新では物理時刻を進めない．

時間方向のブロッキングは，更新間の依存を守って小領域ごとの実行順序を変え，複数回の
更新でデータを再利用してメモリ転送や通信を減らす最適化である．内側では，この
「時間方向」は物理時間ではなく求解の反復回数に対応する．空間並列化と区別して評価する．

### 名前付きの反復ブロック

内側の計算は関数化せず，外側の処理の中に `iterate NAME:` として書く．
ブロックは `field` と `init`・`step`・`check` を持つ．
`return`・`returns`・`result:` は設けない．

最外側のモデルにも，`init`・`step` と同列に任意の `check` を置ける．
内側の `iterate` は `check` を必須とし，最外側では省略できる．

次は軸対称なテイラー・クエット流れの圧力補正を示す擬似コードである．
速度 `u` は半径方向・周方向・軸方向の三成分を持ち，`p` は密度で割った圧力を表す．
数値解法の全体ではなく反復構文の例であり，初期条件と境界宣言の詳細は省略する．

```text
step:
  local u_star = predict_velocity(u, p, nu, dt)
  local rhs = div_h(u_star) / dt

  iterate pressure:
    field phi : scalar @ collocated

    max_steps = max_iters
    check_every = check_interval

    init:
      phi = 0

    step:
      local residual = rhs - L(phi)
      phi' = phi + omega * residual / poisson_diagonal

    check:
      let residual_norm = global_max(abs(rhs - L(phi)))
      residual_norm <= divergence_tolerance / dt

  u' = u_star - dt * grad_h(pressure.phi)

  local p_next = p + pressure.phi
  let p_mean =
    global_sum(cell_volume * p_next) / global_sum(cell_volume)

  p' = p_next - p_mean
```

`predict_velocity` は移流・粘性・遠心力・現在の圧力による予測と回転壁の速度条件の
適用を表す．`div_h` と `grad_h` は格子上の発散と勾配であり，境界も含めて
`L(phi) = div_h(grad_h(phi))` と整合させる．`poisson_diagonal` はこの演算子の
中心点の係数で，この符号では負になる．`omega` は反復の更新量を調整する重みである．
これらの補助計算も Formurae に記述する．

上の射影では，残差 `rhs - L(phi)` と補正後の速度の発散との関係が
`div_h(u_next) = dt * (rhs - L(phi))` になるため，発散の許容値から終了条件を決める．
円筒座標の `cell_volume` は半径による体積の違いを含む．実際の例題では右辺と壁からの
流出入の整合も検査する．壁での圧力補正の条件は予測速度と整合させ，物理的な圧力の
境界条件と区別する．これらの境界宣言の詳細は，反復構文とは別に詰める．

### 状態と変数の参照範囲

- ブロックに入るたびに `init` を一度実行し，内側の状態を初期化する．
- 外側の場・スカラー値は読み取り専用で参照し，内側の反復中には変化しない．
  外側の値を内側の `step` から更新することはできない．
- 無印の `phi` はその回の開始時の状態，`phi'` は次の反復の状態である．
  定義済みの `a'` を後続の式が明示的に読む規則も既存の `step` にそろえる．
  `step` 全体が完了した時点で次の状態が確定する．
- `check` は確定した現在の状態を読み，状態を更新しない．最後の式は全領域で共通の
  真偽値とする．`check` 内の `return` や戻り値のレコードは使わない．
- `init`・`step`・`check` の中の `local`・`let` は，それぞれの区分内でのみ参照できる．
- 正常終了後は，外側から `pressure.phi` のように内側の宣言済み状態を読み取れる．
  書き換えることはできない．`pressure.iterations` は実行した内側の `step` の回数である．
  これらの参照はブロックより後の，同じ外側の処理の中で有効である．
- 外側の次の物理時間ステップで同じブロックに入ると再び初期化する．前回の解を
  初期値に使う場合は，外側で保持した値を `init` が明示的に参照する．

### 内側の判定の順序と失敗時の動作

1. ブロックの固定入力と実行設定を確定し，`init` を実行する．
2. 更新回数ゼロで `check` を実行する．真なら，更新せずに正常終了する．
3. 未収束なら `step` を指定回数実行してから再び `check` を実行する．
4. 真になった場合だけブロックより後の計算へ進む．

`max_steps` はこのブロック内の更新回数の上限で，非負の整数とする．
`check_every` は正の整数で，既定値は 1 とする．上限まで残った回数が
`check_every` より少なければ，その残りだけ更新して検査する．上限を超えて実行しない．
上限ちょうどで `check` が真になった場合も正常終了とする．

上限に達しても偽の場合，または判定時の状態や計算値に NaN・無限大などの数値異常が
ある場合は，診断を出して実行を停止する．最大値などの集計で数値異常を隠さない．
外側の時間ステップは完了させず，物理時刻も進めない．

これは反復の標準動作である．呼び出し側に収束確認の `require` を書かせず，
`pressure.status` も通常の参照項目に設けない．診断には少なくともブロックの名前と
ソース位置，更新回数，停止理由を含める．判定に使った数値の表示方法は実装時に詰める．

### 任意の最外側の check

最外側の `check` も，状態を更新せず，最後の式として全領域で共通の真偽値を返す．
例えば，流れが時間によって変化しない定常状態に近づいたことを終了条件にできる．

```text
init:
  ...

step:
  ...
  iterate pressure:
    ...
    init:
      ...
    step:
      ...
    check:
      global_max(abs(rhs - L(phi))) <= pressure_tolerance
  ...

check:
  global_max(steady_residual(u, p)) <= steady_tolerance
```

`steady_residual` は，現在の状態が定常状態の方程式をどれだけ満たしているかを表す
非負の指標を，Formurae のステンシル演算で計算する補助関数の略記である．
外側の `step` 内の一時値を最外側の `check` から直接参照することはできない．
現在のモデルの状態から計算するか，必要な量を外側の状態として保持する．

- `check` がある場合は，モデルの初期化完了時と，最外側の `check_every` で指定した
  更新回数ごとに判定する．既定の間隔は 1 で，内側の判定間隔とは独立である．
  `first_step` を使うモデルでは初期化のためのその処理も終えてから最初の判定を行う．
- 更新後の判定は，内側の反復と外側の更新，その時点で適用する `filter`，現在の
  ステップ数の更新が完了した状態を読む．内側の一回の更新では外側の判定を行わない．
- 真になったらモデルの時間発展を正常終了する．初期状態で真なら物理時間を進めない．
  最終状態と実行したステップ数を保存し，呼び出し側で出力や終了処理を行えるようにする．
- 終了が確定した後は，追加の更新を行わない．最外側の正常終了に `require` は不要で，
  プロセスをエラー終了させる処理でもない．数値異常や内側の反復の失敗は，従来の設計
  どおり全体の異常終了として扱う．
- `check` を省略した場合，モデル側の終了条件は設けず，実行用 C が総ステップ数などを
  決める．内側の `iterate` に `check` があるかどうかとは独立である．

終了条件の評価は生成された計算本体が担当する．実行用 C はその完了通知を読んで
ループを終了するため，残差などの数値計算や判定式を書き直す必要はない．
C 側の関数名と具体的な受け渡し方法は未決定だが，例えば次のような形を取れる．

```c
/* 新しい C 接続方法の案．現在の生成 API にはない． */
Formura_Init(&argc, &argv, &n);
while (!Formura_Finished(&n)) {
    Formura_Forward(&n);
    /* 必要な時点の出力 */
}
/* 初期状態で終了した場合も含め，最終状態の出力と終了処理を行う． */
Formura_Finalize();
```

この例では完了通知を生成側が保持し，完了後の `Formura_Forward` は更新せずに戻る．
`check` 付きモデルの実行用 C も，完了通知を読んで終了するように更新する．
`main` の自動生成はこの追加の前提としない．

### 全領域集計と実行順序

`global_sum`・`global_max` などは，領域分割された格子全体を集計し，全プロセスで
共通の実行時の値を返す．境界計算のために複製した格子点は重複して数えない．
集計は `check` に限定せず，`init`・`step` と外側の計算でも使用できる．
その値を使う後続の計算は，集計が完了してから実行する．

反復への進入と終了，集計の実行順序は全プロセスでそろえる．格子点ごとに異なる条件の
下で反復や全領域集計を実行する記述は認めない．数値異常や上限到達時も全体で停止し，
一部のプロセスだけが後続へ進んだり通信を待ち続けたりしないようにする．

### 空間並列化を行う基本の実行方式

同じ格子を使う外側と内側では，プロセスへの領域の割り当てと通信環境を共有する．
外側の一ステップを次の順に実行する．

1. 担当領域ごとに予測速度と右辺を計算する．内側の反復中はこれらの値を固定する．
2. 内側の場を初期化し，更新回数ゼロで判定する．配列の記憶領域は再利用してよいが，
   初期値は毎回 `init` の指定どおりに作る．
3. 未収束なら，担当領域の次の状態を計算する．例のヤコビ反復では，すべての格子点が
   同じ反復回数の旧状態を読む．読み取り中の旧状態を上書きせず，更新前後を分離する．
4. 内側の状態を確定し，`k` だけを進める．所定の判定時点または上限なら，この新しい
   状態から残差を計算し，各担当領域の最大値を全領域で集計する．全プロセスが同じ
   継続・収束・失敗の判断に従う．未収束で上限未満なら 3 に戻る．
5. 収束した場を使って外側の速度・圧力を補正する．圧力平均などの集計値は，必要な
   箇所へ渡してから後続を実行する．外側の更新と所定の `filter`，ステップ数の更新を
   終えた後，指定された時点で外側の `check` を行う．

必要な境界条件を各段階で適用する．隣接プロセスから近傍格子点の複製を受け取る通信
（ハロー交換）も，更新や残差の計算に必要な値が届くように配置する．固定入力についても，
参照範囲を満たす値を用意する．待つ範囲はデータへの依存から決め，各ステンシル更新に
無条件の全プロセス待ち合わせは追加しない．全領域集計の結果を必要とする箇所では，
集計の完了を待つ．内側をブロッキングする場合も，この基本方式の計算の意味を保つ．

### 内側専用の状態と反復回数の管理

現行の `MachineProgram` は一つの状態型と `init`・`step` の計算グラフを持つ．
生成された `Formura_Navi` には `time_step`，格子の情報，通信の情報が入り，
コード生成は共通の `step_input`・`step_output` とブロッキング用配列を参照する．
この構成を，反復ごとの状態と実行情報を指定して生成できるように拡張する．

#### 共有する情報と分ける情報

以下は論理的な構成であり，生成する C の型名や配列配置を確定したものではない．

| 情報 | 所有する単位 | 圧力求解の例 |
|---|---|---|
| 物理的な格子，領域の担当，隣接プロセス，通信環境 | モデル全体 | 外側と内側で共有する |
| 外側の確定状態，外側の更新回数，物理時刻 | 外側の反復 | `u`・`p` と外側の回数 `n` |
| 更新する場の現在値と次の値 | 各反復ブロック | `phi` の更新前後の格納先 |
| 内側の更新回数と次の判定時点 | 各反復ブロック | `k` と判定対象の回数 |
| 固定入力 | 各ブロックの実行中に保持する参照と値 | `rhs` の読み取り専用参照，許容誤差などのスカラー |
| 反復の実行設定 | 各ブロックの進入時に確定 | `max_steps`・`check_every` |
| ブロッキング設定と作業領域 | 各ブロックの計算に対応 | `T_inner`，一時配列，通信に使う配列 |

格子を共有する場合も，各場の格子配置・境界条件・近傍の参照範囲は個別に保持する．
内側の一回の更新では `k` だけを進め，外側の `time_step` と物理時刻は変更しない．
`pressure.iterations` は正常終了時の `k` を読む参照になる．内側の結果を用いる
外側の更新が完了して初めて，外側の状態と更新回数を確定する．

#### 更新前後の配列と固定入力

最初の実装では，内側の更新前後を別の格納先に置く．例えば二つの配列 `phi_a` と
`phi_b` の一方を現在値，他方を次の値として使い，更新後に役割を交換する．
複数の場を持つブロックでは，すべての場の更新を終えてから次の状態を確定する．
ブロッキング時は小領域の作業配列を使ってよいが，同じ更新前後の参照規則を保つ．

外側の値を固定するために，すべての場を毎回コピーする必要はない．コンパイラが
書き換えと記憶領域の再利用を禁止できる間は，元の配列への読み取り専用参照を渡す．
`rhs` や `u_star` のような一時的な場が反復の前後で必要な場合は，必要な範囲を配列に
保存する．`rhs` は求解中，`u_star` は速度補正まで有効な値として保持する．
一時値であっても，反復を越えて使う値を，格子点ごとの局所変数だけに置いてはならない．

内側の各ブロックには，ソース中の出現位置から一意の識別子を割り当てる．異なる場所で
同じ名前を使っても，生成する配列と回数が衝突しないようにする．配列はモデルの開始時
などに用意して繰り返し使い，進入時に `k = 0` と `init` の初期値を設定する．
毎回のメモリ確保や，前回の解の暗黙の引き継ぎは行わない．

正常終了後の `pressure.phi` は，最終状態が入った格納先への読み取り専用参照とする．
ブロックを抜けた直後にその配列を作業用へ転用せず，外側での最後の参照が終わるまで
保持する．最終状態を常に決まった配列へコピーすることは要求しない．

#### 反復回数と判定の制御

次は生成コードの制御を説明する擬似コードである．表層言語への関数・`return` の追加を
意味しない．判定は数値異常の有無を含めて全プロセスで同じ結果になるように生成する．

```text
固定入力を保持し，実行設定を確定・検査する
current = init の結果
k = 0

loop:
  current に対して check を実行する
  数値異常があれば全体を異常終了する
  条件が真なら loop を抜ける
  k == max_steps なら未収束として全体を異常終了する

  stop = k + min(check_every, max_steps - k)
  while k < stop:
    q = min(T_inner, stop - k)
    current から q 回の更新を実行し，current を更新する
    k = k + q

pressure.phi は current を参照する
pressure.iterations は k を参照する
外側の残りの計算を続ける
```

ブロッキングなしの場合は，一回ずつ更新する．ブロッキングありの場合も，`q` 回の
内部更新は元の各 `step` の意味を保つ．内側の更新回数が必要な処理には，区間の開始回数
と区間内の回数から求めた値を渡し，外側の回数と混同しない．
短い残りの区間は，初期実装では一回更新の処理を繰り返して対応してよい．
これにより，固定幅のブロッキング生成を再利用しつつ，判定時点と上限を超えずに済む．
`max_steps = 0` の場合も初期状態で判定し，真なら成功，偽なら失敗する．

#### ブロッキング時の配列上の位置

現行の周期境界のブロッキングでは，更新に伴って配列と格子点の対応がずれ，
`Formura_Navi` の `offset_*` も調整される．これを内側から外側の情報へ直接適用すると，
固定入力や外側の場との格子点の対応が壊れるおそれがある．

物理的な領域の位置と，作業配列の位置の調整を分ける．内側の更新が変えるのは後者で
あり，固定した `rhs` は常に対応する同じ物理格子点から読む．最初の実装では，
ブロッキング区間の終わりに結果を元の領域配置へ戻してから，集計と外側への受け渡しを
行う方式を採る．位置の調整を持つ参照を引き継いでコピーを省く方式は，その後に検討する．
配置を戻す際は，元の担当領域の値が各プロセスにそろうために必要な通信も生成する．
このコピーや通信の費用も，内側のブロッキングの性能評価に含める．

共有する通信環境には，反復ごとのデータと参照範囲を渡す．初期実装では各区間で必要な
送受信を完了させてから通信配列を再利用し，前の反復の通信と取り違えないようにする．
固定入力の参照位置が正しいことを，座標によって値が変わる右辺でも検証する．

### Formura への変換

反復ブロックを中間表現と `.fmr` まで保持し，内側の `init`・`step`・`check` と，
それらを繰り返す制御部分を Formura が C に生成する．数式の記号処理中に反復を
実行したり，Formurae が Formura を迂回して反復用 C を生成したりしない．

内側の `init` は反復状態だけを初期化する．外側と格子・並列通信の環境を共有し，
MPI の初期化や外側のモデルの初期化を繰り返さない．反復ごとの境界処理を適用し，
内側の更新回数を外側の物理時間から分離する．

内側では，全領域集計と終了判定が課す依存関係を保って複数反復をブロッキングする．
外側は圧力求解と補正を終えてから次の物理時間ステップへ進む．このモデルの外側に
既存のブロッキングをそのまま適用せず，内側の反復を扱う生成経路を設ける．

外側の実行用 C は従来どおり `Formura_Forward` を呼び出せる構成とする．
内側の圧力求解や最外側の終了判定式を実行用 C に手書きしない．最外側の正常終了を
通知して最終状態を読めることと，失敗時に MPI 全体を停止することを区別する．
具体的な C 側との接続方法，反復用配列の確保と再利用の詳細は，コード生成の設計で決める．

中間表現では，一つの大きな計算グラフだけにまとめず，ステンシル計算，全領域集計，
入れ子の反復を順に実行する構造を持たせる．各反復には，状態の宣言，固定入力，
`init`・`step`・`check` の処理を対応させる．各ステンシル部分の数式は，既存の計算グラフと
格子点の計算を生成する処理を再利用する．外側の例は，予測・右辺，内側の反復，
速度補正，圧力平均の集計，圧力補正という順序になる．

場の読み取りには，どの反復に属する値か，更新前後のどちらか，固定入力かを保持する．
コード生成へ渡す配列と反復回数も，この情報から選ぶ．現在の `step_input` などを
反復ごとに指定する仕組みに変え，同じ `Formura_Forward` と `Formura_Navi` を
再帰的に呼び出して内側の実行を代用しない．表層構文はネストしたまま，生成 C の内部で
計算を補助関数に分けることは許される．

### 内側の時間方向ブロッキング

内側のまとめる幅を `T_inner` とする．これは最適化の設定であり，終了条件を検査する
間隔 `check_every` とは別である．設定の具体的な記法は未決定である．

次の判定時点と `max_steps` のうち早い方までを実行範囲とし，その区間内で複数反復を
まとめる．内側の `step` 自体に集計値を読む箇所がある場合は，その依存も守る．
ブロック幅より短い残りの区間も正確に実行し，上限を超えて更新しない．
ブロッキング中の境界処理と近傍参照には，内側の反復回数に応じた状態を使う．
固定入力は区間全体で参照する範囲を満たすように用意する．

例えば `check_every = 8`，`T_inner = 4` なら，判定までの八回の更新を四回ずつ
ブロッキングできる．集計は八回の更新が全領域で完了した状態から行う．
これは内部で四回ずつ単に関数を呼ぶという意味ではなく，小領域で複数反復のデータを
再利用する実行順序を生成するという意味である．

**`check_every = 1` で毎回全領域判定を行う例では，判定の間に複数反復をまとめる
余地はない．** この場合に `T_inner` だけを大きくしても，複数反復をまたぐ再利用は
得られない．空間並列化は適用できる．判定間隔はユーザーがモデルの実行条件として
明示的に選び，コンパイラは効率化のために間隔や許容誤差を変更しない．

判定間隔を大きくする場合も，初期状態と上限での判定，未収束時の停止という規則は
変えない．指定した判定時点の間では収束を検査しないため，毎回判定する場合より
余分に更新する可能性がある．一般の条件が一度真になった後も真のままとは仮定しない．
この違いを隠して，判定間隔をブロック幅に自動的にそろえない．

### 外側のブロッキングを今回の対象から外す理由

圧力求解の終了判定は，全領域の結果を待ってから，どの近似解を外側へ渡すかを決める．
圧力平均などの集計値を後続の数式が読む箇所もある．そのため，ある小領域だけで
内側の求解を終え，次の物理時間ステップまで進める実行順序を，既存のブロッキングから
直接導くことはできない．効率のよい方式が確立したとはまだ言えない．

今回の設計では，この依存を保つ通常の外側の実行と，内側の反復間のデータ再利用を
採用する．外側のブロッキングや，終了回数を仮定して後続を先に計算する投機実行は
実装対象に含めない．将来再検討する場合は，計算結果と終了判断を保てる方式と，
追加の計算・記憶領域・通信を含めた性能を別に検証する．

先行研究として調べた Reguly ほかの
[Loop Tiling in Large-Scale Stencil Codes at Run-time with OPS](https://arxiv.org/abs/1704.00693)
でも，制御判断に集計値が必要になる地点では待機していた処理を実行する（§IV-A）．
Li・Song の [Automatic Tiling of Iterative Stencil Loops](https://www.cs.purdue.edu/homes/ci/draft/toplas.pdf)
は投機実行と状態の復元を扱うが，§6.3 の区間末尾だけを調べる方式には，終了条件が
一度真になると真のままという前提がある．任意の `check` と全領域の圧力求解を含む
外側のブロッキングへの一般解とは扱わない．

### 実装と評価の順序

1. 反復構文と中間表現を追加し，通常の生成経路で，単一プロセスでの状態更新・判定・
   終了を確認する．これを最適化の比較基準とする．
2. 外側と内側の各計算を同じ領域分割で実行し，境界・ハロー交換・全領域集計・全体での
   終了を確認する．ここで格子点の空間並列化を成立させる．
3. 判定の間で行う内側の時間方向ブロッキングを追加し，判定時点と上限，解と終了判断を
   保つことを確認する．適用範囲は判定間隔とデータへの依存から決める．

空間並列化は，同じ問題の大きさでプロセス数を増やしたときの実行時間で評価する．
内側のブロッキングは，問題・初期状態・格子・時間刻み・許容誤差・判定間隔・並列構成を
固定し，ブロッキングなし／ありを比較する．数値計算はどちらも Formurae に記述する．
判定間隔を変えたことによる効果は，ブロッキング自体の効果と分けて報告する．

実行時間に加え，メモリ転送量，近傍領域の通信量，全領域集計の回数と待ち時間，追加の
計算量と配列量を記録する．正しさの比較では，最終値に加えて所定の判定時点と終了時点，
更新回数，失敗時の動作を確認する．集計順序による浮動小数点誤差が終了判断へ与える
影響も切り分ける．

## 差し込み口

- Formurae の `src/Formurae/Syntax.hs` と `src/Formurae/Pre/Parse.hs`：
  入れ子の処理と区分，最外側の任意の `check`，名前の参照範囲，実行設定を表す構文を追加する．
- `src/Formurae/Pre/TypeCheck.hs` と `src/Formurae/Pre/Effect.hs`：
  場と全領域で共通の値，外側の固定入力と内側の更新対象を区別して検査する．
- `src/Formurae/Pre/EmitEgison.hs`，`src/Formurae/FEIR/`，`lib/` の FEIR 出力：
  反復・集計・処理順序・ソース位置を保って受け渡す．
- `src/Formurae/Post/Compile.hs` と `src/Formurae/Post/FMR.hs`：
  反復単位の格子配置と一時的な場を決め，拡張後の Formura 構文へ変換する．
- Formura の `Parser.hs`・`Syntax.hs` と `OrthotopeMachine/`：
  現在の単一の `init`・`step` に加え，内側の反復と実行時スカラーを表現する．
  `MachineProgram` を，反復ごとの状態と固定入力，計算と集計の実行順序を持つ構成へ拡張する．
- Formura の `Generator/Templates.hs` など：
  反復制御，ステップ途中の全領域集計，最外側の終了判定と完了通知，失敗時の停止，
  通信と境界処理を生成する．
  現在の `genReduces` は呼び出し完了後の状態の集計なので，その配置のままでは不足する．
  配列・回数・作業領域の参照を反復ごとに渡せるようにし，物理的な格子の位置と
  ブロッキング中の配列の位置を分離する．
- Formura の計算の依存関係を調べる処理とブロッキング生成：
  内側の更新前後の状態，固定入力の参照範囲，集計への依存を表現し，
  所定の判定時点までの反復をブロッキングする実行順序を生成する．

## 完了条件

- 入れ子の `init`・`step`・`check` と終了後の状態参照が通常の生成経路で動作する．
  外側の値への書き込みや，区分外の一時値の参照をソース位置付きで検出する．
- 最外側の `check` の有無，初期状態での正常終了，更新後の正常終了，内側と異なる
  判定間隔を検証する．終了後の追加更新を行わず，最終状態を C 側から出力できる．
  初期化用の `first_step` と更新後の `filter` がある場合の判定順序も確認する．
- 初期状態での収束，通常の収束，上限ちょうどでの収束，未収束での上限到達，
  判定間隔で割り切れない上限，数値異常を検証する．失敗時に後続処理や外側の時刻更新が
  実行されないことを確認する．
- 固定入力の保持，複数の反復状態の更新前後の参照，ブロックへの再進入時の初期化を
  検証する．内側の反復回数で外側の物理時刻が変わらないことを確認する．
- 異なるブロックの状態・回数が衝突せず，終了後の場が外側の最後の参照まで保持される．
  ブロッキング時も座標依存の固定入力と内側の場が同じ物理格子点を参照し，外側の
  配置に影響しないことを確認する．奇数回と偶数回の更新後の状態参照も検証する．
- 格子全体の集計が一時的な場にも使え，その値を後続の式に渡せる．単一プロセスと
  分割実行で，適切な浮動小数点の許容誤差の下で同じ計算を行うことを確認する．
- 外側の予測・補正と内側の初期化・更新・残差計算が空間方向に並列化され，同じ
  領域分割を使う．プロセス数を変えた評価と，ブロッキングを切り替える評価を区別する．
- 同じ判定間隔の下で，ブロッキングの有無と領域分割の違いによる解・判定の整合を
  検証する．境界と固定入力を含む例を用い，未収束・数値異常でも通信待ちが残らない．
- 内側のブロッキングなし／ありで比較し，同じ判定間隔と並列構成での実際のデータ
  再利用と性能への効果を示す．ブロック幅と判定間隔が異なる場合や，上限までの残りが
  短い場合を検証する．外側の時間方向ブロッキングは完了条件に含めない．
- 単独のポアソン問題と速度補正の例で，解の誤差と方程式の残差，補正後の発散を
  検証する．これらの数値計算を Formurae に記述する．
