# 巻き込む波と引き波

北斎の『神奈川沖浪裏』に見られる，波頭が前へせり出す形を目標にした，
横から見た二次元の水槽である．1つの初期波を浅瀬へ進ませ，波頭が崩れ，
水が斜面を上り，沖側へ戻る引き波まで計算する．

![1つの波と引き波](results/wave.png)

[動画](results/breaking-wave.mp4) · [時間変化](results/sequence.png) ·
[Formuraeソース](breaking_wave.fme)

白線は計算した水面，矢印は計算した流速を示す．破線の観測位置を横切る水量は，
岸向きが正，沖向きが負である．描画で波や飛沫を追加したり，動画を逆再生したりしない．

384×96点で9,000ステップを計算した．動画は151フレーム，12 fps，約12.6秒である．
60ステップごとの検査では水量の最大相対変化は **7.72×10⁻¹⁵**，最大流速は0.1668，
未配分の質量は1点あたり最大9.18×10⁻¹³だった．水面点の `mass/density` は
−0.130〜1.032で，表示前の一時的な範囲外の値も検査に含めている．

`x = 225` の観測位置では，岸向きの流束が最大1.258となった後，沖向きに変わり，
厚さ2点以上の水の先端が最も岸側に達した後，負のピークは5,760ステップの−0.171だった．4,980〜8,400ステップの間，
流束は−0.01未満を保った．水量・流速・流束はすべて格子単位である．

**沖向きの流れは再現したが，最も岸側の水際は後退していない．**
階段状の海底に薄い水が残り，2点以上の厚さをもつ部分の先端も `x = 350` に留まった．
薄い水まで含めた先端は `x = 351` で，右端の壁には届いていない．
[検証値](results/verification.json)には流れの反転と水際の後退量を別々に記録している．

静水の比較計算（128×96点，1,200ステップ）では，最大流速0.000241，
覆いかぶさり0点，水量の最大相対変化8.51×10⁻¹⁵だった．

## 実行

リポジトリ直下で次を実行する．描画にはNumPy，Matplotlib，ffmpegが必要である．

```sh
make breaking-wave-demo
make breaking-wave-verify
```

`run.py` は `.fme → Egison → FEIR → .fmr → Formura → C` の順に生成・実行する．
FEIRはFormuraeの中間表現である．計算結果を `.build/breaking_wave/demo/` に保存し，
`render.py` が保存済みの場から図と動画を作る．物理的な1ステップは，衝突，移動，
分類，質量再配分，診断の5回の生成された更新で実行する．CSVと動画のステップ数は
物理的なステップ数である．

初期条件，海底，壁，重力，流体と水面の更新，質量の受け渡し，検証用の場は
すべて `breaking_wave.fme` にある．Cは生成関数の呼び出し，出力，検査のみを行う．
Pythonはビルド・起動・ファイル操作・記録値の比較・描画を担当する．
Formura本体の変更や外部の流体ソルバーは使わない．

標準の水槽は384×96点，平水面の高さ36，波高26.25，幅18，波の中心53である．
海底は高さ2から始まり，`x = 90` より右で傾斜0.2となる．重力加速度は
0.00013333333333333334，`tau = 0.59`，初期速度の係数 `launch = 2.5` とする．
9,000ステップまで計算し，60ステップごとに記録する．

水槽の設定は `.fme` の先頭と [metadata.json](results/metadata.json) に記録している．
格子間隔と時間刻みを1とする単位系であり，実際のメートル・秒への換算は行っていない．
初期水面は `depth + amplitude/cosh((x-center)/width)^2`，初期の右向き速度は
`launch*sqrt(gravity*(depth+amplitude))*elevation/height` とする．
これは厳密な進行波解ではなく，巻き込みと引き波を調べるために指定した初期条件である．
斜面の先まで計算領域を確保し，水が右端の壁に達する前に引き波を観察する．

## 添字と計算法

格子ボルツマン法（格子点間を移動する分布から流れを求める方法）の
二次元・九速度モデルD2Q9を用いる．空間の次元と分布の成分数は別々に指定する．

```text
dimension 2
axes x, y
index a : 9
field f_a
field savedG_a
field savedS_a
```

`f_a` は9種類の移動速度に対応する分布，`savedG_a` と `savedS_a` はそれぞれ
衝突後と移動後の分布である．`f_1` は静止成分，`f_2`〜`f_9` は周囲8方向を表す．
2成分の流速と密度は，縮約（同じ上下の添字について成分の和を取る演算）で求める．

```text
local rho = ones~a . f_a
local u_i = (directions~a_i . f_a)/rho - [| 0,gravity/2 |]_i
```

重み `weights` と移動方向 `cx`・`cy` を一度だけ定義し，Egisonの
`generateTensor`（成分番号を受け取る関数からテンソルを作る演算）で9成分を生成する．
Formuraeでは既存の `def` 本体で利用できる．初期化は次の形となる．

```text
def equilibriumPopulations r u v =
  generateTensor (\[q] -> equilibrium weights_q cx_q cy_q r u v) [9]

init:
  f_a := (equilibriumPopulations initialDensity initialU 0)_a
```

同じ関数を衝突計算と新しい水面点の初期化にも使う．重力の項と壁・空気に接する点の
分布の再構成も，それぞれ9成分を生成する関数にまとめている．成分番号 `q` は1〜9の整数であり，
結果に付ける添字記号 `a` と区別する．成分の生成は正規化時に行われ，通常のFormura配列へ変換される．
条件分岐も成分ごとの列挙を避け，例えば次のようにテンソル全体へ適用する．

```text
savedG'_a = if stage < 0.5 && stage > -0.5 then g_a else savedG_a
```

### 中間値の保持

物理的な1ステップを構成する5回の更新のうち，`f`・`mass`・`kind` を変更するのは
`stage = 3` である．`rho`・`u_i`・`eps` はそれより前に使うため，元の状態からその場で
計算できる．保存用の `savedRho`・`savedU_i`・`savedEps` は不要なので削除した．
`local u_i` の数値成分 `u_1` も通常のスカラーとして扱う．

衝突後の分布 `savedG_a`，移動後の分布 `savedS_a`，次の分類や再配分用の量は，
複数の更新にまたがる中間状態として保持する．`field ... : scalar` は格子点ごとに
1つの値を保持する宣言であり，水槽全体で1つの変数という意味ではない．

[リファクタリングの比較記録](results/refactor.json)では，削除した4スカラー成分への参照を
対応する局所変数に置き換えると，残る317個の生成式がすべて一致することを確認した．
さらに，9,000ステップの検証値と151フレームの全9出力場が変更前とバイト単位で一致した．
[静水の比較](results/still/refactor.json)でも，1,200ステップの検証値と21フレームが一致した．
保存済みの2つの実行結果は次のコマンドで照合できる．

```sh
python3 examples/breaking_wave/verify_refactor.py \
  .build/breaking_wave/demo-before-tensor-refactor .build/breaking_wave/demo \
  --output examples/breaking_wave/results/refactor.json
```

### 流体と水面の計算

`ones` は9個の1，`directions` は9×2成分の速度の表である．
重力には [Guo・Zheng・Shiの力の項](https://doi.org/10.1103/PhysRevE.65.046308)を用いる．
分布を平衡状態へ近づける緩和時間 `tau` と，流れの粘性を表す動粘性係数の関係は
`ν = (tau - 0.5)/3` である．

水面には [Thüreyの自由表面法](https://www10.cs.fau.de/publications/dissertations/Diss_2007-Thuerey.pdf)
を用いる．自由表面とは，ここでは水と一定圧力の空気との境界である．

1. 各点を空気・水面・水・固体に分類し，分布と質量を保持する．
2. 分布を緩和させて重力を加え，隣接点から移動させる．固体では反射させ，
   空気側からの分布は一定気圧の条件から再構成する．
3. 隣接点との流束（点の間を出入りする質量）で水量を更新する．水面点どうしでは
   水の占有率（各点を水が占める割合）の平均を使う．
4. 満ちた水面点は水へ，空になった水面点は空気へ変換する．水と空気の間には水面点を置く．
5. 分類変更による余剰・不足の質量を近傍の水面点へ配る．受け取り先のない量は
   `bank` に保存して後で再配分し，捨てたり全領域へ補正したりしない．

### 長時間計算に向けた修正

以前の更新では，ごく小さい水面点が残って加速し続け，引き波の前に流速が検査範囲を
外れる場合があった．上記文献の水面の分類に応じた流束補正を追加した．
水に接しない水面点からは水を出し，空気に接しない水面点には水を入れる．
どちらも，相手側の流束を逆符号とすることで2点間の質量保存を保つ．
さらに，今回新しく満ちた点・空になった点を，既存の水・空気と区別する．
新しく満ちた点を水として残し，その外側に水面を作ることで，水面が前へ移動できる．
満ちる点に隣接した空になる予定の点は水面として残し，その変更を反映してから
既存の水を水面へ変える．この順序を守ることで，不要な分類の往復と質量の蓄積を防ぐ．

通常の分類切り替えのしきい値 `threshold = 0.001` と，水・空気の一方に接しなくなった
点を整理するしきい値 `lonelyThreshold = 0.1` を分けた．同じ区別は
[OpenLBの水面分類の実装](https://www.openlb.net/DoxyGen/html/d9/d83/classolb_1_1FreeSurfaceInterfaceReconstructionPostProcessor2D.html)
でも確認できる．流速の切り詰めや検査範囲の緩和は行っていない．

[添字宣言への移行検証](results/index-migration.json)は，この修正より前の1波モデルについて，
式の一致と60ステップの結果の一致を確認した過去の記録である．今回の結果は，修正後の
`.fme` から改めて計算し，ソースのSHA-256を実行条件に保存する．

## 検証する量

以下は60ステップごとの記録値で検査する．全内部ステップの最大値を記録するものではない．

- `water`：質量と保留量 `bank` の総和．最大相対変化10⁻⁹未満を確認する．
- `bank` と `bank_total`：保留量の1点あたりの最大絶対値と絶対値の総和．ともに10⁻⁶未満を確認する．
- `bad`：密度が0.5より大きく1.5未満，流速が0.3未満という条件を外れる点と，
  補正前の `mass/density` が−0.5〜1.5を外れる水面・水の点を数える．0を要求する．
- `fraction_min`・`fraction_max`：表示用に0〜1へ制限する前の `mass/density` の範囲．
  再配分直後の一時的な行き過ぎも含めて記録し，負の質量が蓄積する状態を検出する．
- `overhang`：占有率が0.5を超え，直下が0.5未満かつ固体でない点数．
  飛び離れた水滴も数えるため，巻き込みの形は動画でも確認する．
- `shore_flux`：`gaugeX` の鉛直列における `mass*velocityX` の総和．引き波では負になる．
- `wet_front`：固体の海底に直に接し，水の占有率が0.5を超える点のうち最も岸側の位置．
  飛び離れた水滴は含めない．
- `bulk_front`：海底に接する水が鉛直方向に2点以上続く部分の先端．1点程度の薄い水を
  区別するための記録である．先端の後退量は，沖向きの流れとは別に報告する．

引き波の検査は，観測位置で岸向きの流束が0.05を超えたあと，最大遡上後に沖向きの
流束が−0.05を下回り，−0.01未満の流れが600ステップ以上続くことを要求する．
水際の後退は別の指標であり，引き波の存在だけから後退を仮定しない．薄い水を含む最も岸側の位置が，
右端から8格子以上離れていることも検査する．静水の比較計算では，最大流速0.001未満と覆いかぶさり0点を確認する．

## 適用範囲

空気の流れ・気泡の圧縮・表面張力は含まない．海底は格子に沿った階段状の固体である．
薄い水が海底に残るため，今回の計算では最も岸側の水際の後退は再現できていない．
水量保存と戻る流れを検査した二次元の試作であり，細かな白波・飛沫，
実海域の波の定量的な予測，実験との比較，格子を細かくした際の誤差評価は今後の課題である．
複数プロセスによる領域分割と複数時間ステップをまとめる最適化は，この例では未検証である．
