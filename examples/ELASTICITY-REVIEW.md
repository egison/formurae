# 弾性波の例題調査（2026-09-10）

既存の Formura で実行できること，MPI による領域分割（複数プロセスへの計算の分担）と
時間方向のブロッキング（複数ステップをまとめて計算する最適化）を使えること，
初期条件・更新・検証用の物理量まで Formurae に記述されていることを確認した．
この調査では新たなコンパイル，数値計算，並列性能測定は実行していない．

| 例 | 境界と高速化機能 | 初期条件・更新 | 検証量 | 判断 |
|---|---|---|---|---|
| 円筒座標 `elastic_cylindrical` | 非周期境界により単一プロセス・ブロッキングなし | 更新は `.fme`，実験用初期値は C | エネルギーなどを C で計算 | ユーザーの指示により削除 |
| 球座標 `elastic_spherical` | YAML は `[fixed 0.0, fixed 0.0, periodic]`。2026-09-12 の Formura 拡張により時間ブロッキング（間隔 2）を使用。単一プロセス | 更新は `.fme`，実験用初期値は C | 共通の C 検証コードを使用 | 初期値と検証量の `.fme` 化は未着手 |
| 直交座標 `elastic3d` | 周期境界。4ステップのブロッキングを設定。MPI は1プロセスの設定 | 初期値と更新を `.fme` に記述し，通常の Formura 経路で生成 | エネルギーとパルスの位置・速度を C で計算 | 計算の構造は適している。検証量の実装と並列性能の確認が必要 |

## 境界に関する実装上の制約

円筒・球座標の例は，中心の特異点を含まない殻状領域で，近傍格子点だけを使う
速度・応力の陽的更新を行う．領域全体の連立方程式を解く処理はなく，方程式自体は
Formura の格子計算に適している．

調査時点の Formura の `src/Formura/NumericalConfig.hs` は，非周期境界が一つでも
ある場合に，時間ブロッキングの有効化と `mpi_shape` の2以上の値を拒否していた．
`src/Formura/Generator/Templates.hs` の `noBlockingAnchored` は，原点を動かさない
単一プロセス向けの境界処理を生成する．周期方向だけを MPI で分割する設定も，
この検査では受理されない．

**追記（2026-09-12）**: ユーザー指示により，壁のある軸での時間ブロッキングを Formura の
fork（`tb-boundaries`，`54838f6`・`9c66835`）に実装した．壁のある軸は床の中で
アンカーされ（内部を `2*sleeve*interval - sleeve` の位置に置き，各ブロック・各サブステップで
ゴーストセルを境界値で上書きし，間隔の終わりに再アンカーする），周期軸は従来の
シフト枠のまま動く．`make tb-wall-tests` は，壁を持つ 13 例のブロッキング版が通常版と
全状態変数・全セルでビット一致することを確かめる（周期軸の長さが片側 halo
`2*sleeve*interval` より短い設定は Formura が拒否する）．複数プロセスの分割は
非周期境界では引き続き使えない．

## 初期条件と検証コード

球座標の `.fme` は速度と応力をゼロに初期化する．共通の
`elastic_curvilinear/elastic_check.h` は，解析解または全成分を励起する初期値を
計算して生成プログラムの配列へ書き戻す．エネルギーと独立参照計算も C にある．
波の伝播を収集する C コードも初期パルスを作り，`tools/collect_elastic_ps.py` は
検証用入力の生成と発散・回転の参照計算を Python で行う．これらは描画だけの処理ではない．

`elastic3d/elastic3d.fme` は初期パルスを `.fme` の式と，Formura に渡す
`raw` の関数定義で記述する．C ドライバは生成された場を初期値として使用し，
初期値を上書きしない．ただし `elastic3d/elastic_check.c` の `energy` と `centerOf` は
物理量を C で計算するため，現在の「検証用の物理量まで Formurae に記述する」方針とは
一致していない．`benchmarks/abstraction/manual/elastic3d.fmr` は同例の比較用記述であり，
別の境界・並列実行条件を持つ例ではない．

関連ベンチマークの `benchmarks/abstraction/run.py` は，三方向に変化する初期値を
生成する C コードを組み立て，配列へ書き込む．通常の `elastic3d` の初期化とは
異なり，こちらは初期条件を Formurae に記述する方針にも一致していない．

## 直交座標の例で確認できる範囲

`elastic3d.yaml` は `grid_per_block: [8,8,8]` と
`temporal_blocking_interval: 4` を指定している．全軸が周期境界なので，
上記の非周期境界による禁止には該当しない．
ただし `mpi_shape: [1,1,1]` と，MPI の代用ライブラリを使う現在の通常検査から，
複数プロセスでの正しさや性能を結論できない．通常の数値検査で使う波は x 方向のみに
変化する．上記のベンチマークには三方向に変化する入力があるが，初期値を C 側で
作る構成であり，そこでも MPI は1プロセスの設定である．

単一プロセスの性能記録はある．`benchmarks/abstraction/README.md` によると，
旧 Egison で生成した `64^3` 格子の更新は1ステップ16.059 msで，同じ差分・時間更新を
手書きした Formura の15.274 msに対して1.051倍だった．4ステップ後と計測区間後の
全配列の一致も確認されている．これは直交座標の例の実用性を支持するが，
最新 Egison での再測定や複数プロセスでの性能検証を意味しない．

## 円筒座標の例の削除範囲

`examples/elastic_cylindrical/` のモデル・生成物・実行用ファイルと，
`elastic_curvilinear/diagnostics_cylindrical.fme`，同 `.fmr` を削除した．
Makefile，現在の例題一覧，検証・収集スクリプト，全体モデルを使う比較入力も更新した．
過去の数値データ，結果JSON，研究比較の記録は実測の履歴として保持する．
球座標と直交座標の数値実装および共通ライブラリは変更していない．
