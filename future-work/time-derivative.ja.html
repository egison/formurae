Formurae future work: 時間微分記法 ∂_t(検討のうえ不採用)

検討メモ(2026-07-27)。u' = u + dt * κ * Δ u を ∂_t u = κ * Δ u と書けるようにする案を検討し、不採用と決定した記録。 結論と設計原理は GPCE 原稿 §7(Explicit time stepping 段落)に反映済み。 本メモは反例・棄却した代替案・スイート実測の全体を保存する。

1. 要点 — ∂_t 形は更新則を決定しない

提案は、現行の陽的更新則

step:
  u' = u + dt * κ * Δ u

を PDE そのものの形

step:
  ∂_t u = κ * Δ u

で書けるようにするものだった。空間側はすでに連続作用素(Δ、curl、 ∂_x)で書けるのだから、時間側も揃えたい、という動機である。

不採用の核心は、どの時点の値を右辺が読むか(旧値か更新後値か)はスキームの性質で あって方程式の性質ではないこと。∂_t 形の字面からはこの情報が原理的に復元できず、 注釈・宣言・暗黙規約のいずれかで必ず連れ戻すことになる。その時点で「純粋に PDE のまま 書ける」という売りは崩れ、さらに LBM のストリーミングや診断場のように半離散流ですらない step が言語に残る以上、更新則記法はどのみち廃止できない。記法を二重化する対価がない、 というのが結論である。

2. 決定的な反例 — 同じ字面で逆の答え

∂_t 形では見分けのつかない 2 つの連立系が、逆の参照方針を要求する。

2.1 Maxwell 対 — 更新後値が正しい

step:                          -- examples/maxwell3d_yee
  E' = E + dt * curl B
  B' = B - dt * curl E'        -- E' (更新後) を読むから安定

B の更新が更新後の E' を読むのは symplectic Euler/Yee スキームの本体であり、 波動系のエネルギー安定性はここに懸かっている。∂_t 形 ∂_t B = - curl E と書くとこの選択が消える。

2.2 交換系 — 旧値が必要

∂_t a = k * (b - a)
∂_t b = k * (a - b)            -- 右辺の和は 0 → a + b は保存するはず

両方が旧値を読む(Jacobi)なら a' + b' = a + b が丸めを除いて厳密に成り立つ。 「計算済みの最新値を使う」規約だと

a' = a + dt·k(b − a)
b' = b + dt·k(a' − b) = b + dt·k(a − b) + dt²k²(b − a)
⇒ a' + b' = a + b + dt²k²(b − a)

となり、毎ステップ O(dt²)、時刻 T までで O(dt) の総量ドリフトが生じる。 逐次化(Gauss–Seidel)はむしろ減衰的で安定化するため爆発せず、 保存量を測るまで気づけない。書いた式は「和が保存する」と主張しているのに、 降ろし方が黙ってそれを破る、という最悪の形の silent change である。

2.3 そもそも半離散流でない step

f11' = pullz 1 p11             -- examples/lbm_d3q19: collide–stream の streaming
q'   = divg V                  -- examples/divergence2d: 診断場(時間発展でない)

これらは ODE の時間積分ではないので ∂_t 形に載らない。更新則記法は言語から消せない。

3. 検討した設計案と棄却理由

案 A(最新値優先)で意味が変わってしまうのは次の 2 例。どちらも反応拡散型で、 現行は同時更新(Jacobi)が意図されている。

-- pearson3d: U' が先に計算されるため、V' の右辺の U が U' に化ける
U' = U + dt * (Fu * (1 - U) - Fe * U * V^2 + Du * Δ U)
V' = V + dt * (Fe * U * V^2 - Fv * V + Dv * Δ V)

-- tdgl3d: 同様に b' の右辺の a が a' に化ける
a' = a + dt * (a - (a^2 + b^2) * a + Δ a)
b' = b + dt * (b - (a^2 + b^2) * b + Δ b)

他の Euler 系 21 例が無傷なのは「単一フィールド」「local 経由」「先頭の式だけが他を参照」 のいずれかによる偶然であり、式の並べ替えで壊れる。この脆さ自体が案 A の問題を示している。

5. 採用した設計原理(論文 §7 に記載)

宣言が一意に決定するものは生成し、数値的な選択であるものは式に書く。

宣言が決定 → 生成される数値的選択 → 式に書く
計量係数(metric scale / embedding) 時間積分法(u' = u + dt * R の形そのもの)
境界閉包(boundary x : sbp) 旧値/更新後値の参照(RHS の ')
スタガードのパリティ・幅(profile / 半整数半径) 人工粘性(λ * ∂²_x ρ)・SAT ペナルティ項

既存の標語「計量は宣言であって第 4 の記法ではない」の対句が 「時間積分は式であって宣言ではない」。連続の方程式は -- du/dt = kappa * laplacian(u) のようにモデル先頭のコメントに住む、 という現行慣行を公式のものとする。

6. 字句上の罠(実装済みの現仕様に対する注意)

src/Formurae/Pre/Parse.hs の現仕様では、mark が宣言済み axis でない ∂ は indexed derivative に落ちる(∂_j σ~i~j の j と同じ扱い)。 つまり今 RHS に ∂_t u と書くと「添字 t の空間微分」として黙って解釈される。 将来もし ∂_t を導入するなら、t を time mark として予約し、 (a) RHS への出現、(b) t という名の axis/添字との衝突を静的エラーにする必要がある。

7. 再検討の条件

  • RK 系列の需要が実例で出た場合: time : rk4 宣言+ステージの local 合成(composeStages の時間版)は案 B の枠で追加可能。その場合も表層は ∂_t 形ではなく、更新則記法の中のマクロ/宣言として納める道を先に検討する。
  • 案 D(時間スタガード宣言): 空間の @ primal/@ dual と 対称な時間配置宣言は、一般計量(general-metric.ja.html)と同様の全層波及があるため、 依存マップと費用対効果の評価を経てから。成立すれば Yee 対の prime も消え、 順序非依存になる。
  • いずれの場合も §2.2 の交換系が回帰テストの必須項目(保存量の厳密検査)。
